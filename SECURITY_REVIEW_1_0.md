# Pulse PC 1.0 — проверка безопасности перед релизом

Дата: 22.10.2026. Проверены исходники `modules/local_api.py`, `modules/mobile_access.py` и текущая политика конфиденциальности. Это статический обзор, не результат сетевого тестирования.

## Уже реализовано

- Большинство API-маршрутов требуют Bearer-токен сопряжённого телефона.
- Токены устройств генерируются через `secrets.token_urlsafe(24)`, а на диске хранятся SHA-256 хеши.
- Сопряжение требует подтверждения в диалоге на ПК; есть отзыв доступа.
- Большинство команд блокируется, когда рабочая станция заблокирована.

## Блокирующие вопросы перед публичным релизом

1. **HTTP без TLS.** `web.TCPSite` слушает `0.0.0.0`, а Bearer-токен передаётся в HTTP-заголовке. На недоверенной локальной сети токен может быть перехвачен. Нужен защищённый канал или ограничение безопасным окружением с ясным предупреждением; нельзя заявлять, что весь LAN-трафик шифруется.
2. **Сетевой охват.** Сервер слушает все интерфейсы. `is_private_ip()` проверяет частный адрес клиента для сопряжения, но не доказывает принадлежность к той же локальной сети. Перед выпуском проверить Windows Firewall, VPN и маршрутизируемые частные сети.
3. **Публичные маршруты.** `/api/ping` раскрывает имя ПК без авторизации; `/api/pair` допускает запросы на подтверждение с частных адресов. Нужны ограничение частоты и проверка допустимости входящих запросов.
4. **Ошибки API.** Общий обработчик возвращает `str(exc)` в HTTP 500. Это может раскрывать внутренние пути и детали системы; клиенту нужен общий текст ошибки, подробности — только в локальном журнале.
5. **Передача файлов.** Проверить права доступа к произвольным путям скачивания, ограничения объёма, конфликт имён и параллельные загрузки. Аутентификация не заменяет проверку полномочий пользователя.
6. **Состояние блокировки.** `/api/status`, `/api/events`, `/api/player/state`, `/api/player/cover` доступны авторизованным устройствам даже на заблокированном ПК. Убедиться, что это ожидаемая политика приватности.

## Проверки перед 1.0

- Добавить автоматические тесты на отказ без токена, отзыв токена, запрет управления заблокированным ПК и подтверждение сопряжения.
- Протестировать Windows 10/11, разные сетевые интерфейсы, VPN, отключённый интернет и сопряжение нескольких телефонов.
- Запустить `python -m unittest discover -s tests` в Windows с установленными зависимостями.
- Проверить и обновить `PRIVACY_POLICY.md`, `README.md`, `LICENSE` после изменений реализации.

**Статус:** аудит безопасности не закрыт; официальный релиз 1.0 пока не рекомендован. Этот документ не подтверждает наличие уязвимости в реальном развёртывании без воспроизведения.
